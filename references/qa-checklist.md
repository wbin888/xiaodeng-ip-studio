# QA Checklist

## 先查选点(最重要)

- 遮住标注问“这图在讲啥”,答案是不是本节真正的修辞任务?不是 → 回 `analysis-playbook.md` 重锁点再生成,别只调画面。

## 必过项

- 比例符合方案,方向词一致,没被模型改成方图。
- 纯白背景,无纸纹、阴影、渐变、米色、噪点。
- 有小方,且小方承担核心动作(整合测试:擦掉小方,原位置是结构里的一个洞)。
- 小方没有多余肢体,背景线不穿过身体,道具握在手里。
- 小方外形锁定:白色正面方盒、**一只**大圆眼、**一根**蓝点天线、两条细腿;无嘴、无胶带、非牛皮纸色、非 3/4 侧视。
- 一张图只讲一个核心结构;主体 ≤60%,留白 ≥35%。
- 隐喻是为这篇现编的,没复刻旧案例。
- 解释图:Q4 必现内容逐条都在且正确,数量对;隐喻对照表对得上。
- 对比图:左右两侧是同一个被对比对象。
- 中文标注少、短、无错字;没有色值 / 色名 / 结构类型被画成字。
- 颜色语义正确:橙 = 主路径,红 = 重点 / 问题,蓝 = 补充。
- 全篇视觉契约一致;相邻两张在隐喻物件、构图、小方动作、标注位置中至少 3 项不同。
- 整组分布:情绪图不超过一半;该有解释图 / 四格的没有被情绪图替代。

## 失败信号

- 左上角出现“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 小方像吉祥物、表情包、可爱卡通,或只站在旁边看。
- 小方长出两只眼 / 嘴 / 胶带,或被画成写实快递箱——会和小盒等已有 IP 撞脸,直接重生成。
- 画面像 PPT、课件、正式流程图;元素、箭头、节点太多。
- 文字变成大段解释,或中文错字严重。
- 画面死板,没有荒诞隐喻。
- 很漂亮但画错了重点或机制。

## 迭代修法

| 症状 | 修法 |
|---|---|
| 太普通 | 让小方成为动作主体,加一个奇怪但成立的隐喻 |
| 太复杂 | 删节点,只留一个动作 + 3-5 个短标注 |
| 太可爱 | 强调 deadpan、blank serious expression、not cute、not mascot |
| 太 PPT | 去标题、边框、整齐网格和多余箭头,改成手绘场景 |
| 太像旧案例 | 保留核心意思,换掉主物件和小方动作 |
| 文字错 | 少量错字局部编辑;错得多就减少标注重生成。不用 PS / 代码涂改文字 |
| 机制画错 / 对比散架 / 小方画崩 | 直接重生成,不带瑕疵交付 |
| 方图 / 比例跑偏 | 重生成 |

## 交付判断

- 情绪图:先觉得“有点怪”,1 秒内看懂。
- 解释图:1 秒看懂机制,每个部件对得上原文。

第一眼像教程页,而不是白纸上的怪诞产品草图 → 不合格。
